# ShipOne · 해커톤 제출 초안

## 한 문장

흩어진 할 일과 일정에서 오늘 끝낼 하나를 고르고, 실제 결과물의 근거로 완료를 남기는 PC 개인 에이전트.

## 문제

할 일은 계속 쌓이지만 “오늘 무엇을 끝낼지”와 “정말 끝났는지”는 여전히 사람이 판단합니다. 계획을 많이 세우는 것보다, 지금 가능한 범위를 정하고 하나의 결과물을 남기는 일이 필요합니다.

## 제품 흐름

**Context → One Mission → Focus → Evidence → Receipt**

Notion과 Calendar 또는 직접 입력으로 맥락을 모읍니다. 빈 시간을 계산해 가능한 작업을 추리고, OpenAI가 하나의 Mission과 완료 조건을 제안합니다. 사용자가 시작하면 조건을 잠급니다. 집중 중의 생각은 주차하고, 막힘에는 다음 한 걸음을 제안합니다. 결과물을 내면 확인 가능한 조건부터 검사하고 근거와 함께 기록합니다.

## 보여줄 차별점

- 우선순위 목록에서 멈추지 않고 시작부터 완료 근거까지 한 흐름으로 연결
- 빈 시간의 합이 아닌 **연속된 빈 시간**을 사용
- 자동 검사와 사용자 확인을 구분하여 “완료”를 과장하지 않음
- 완료 조건·근거를 바꾸면 이전 검증을 재사용하지 않음
- PC에 설치해 실제 파일을 고르고, 작업 기록을 로컬에 보관
- 웹은 누구나 흐름을 설명받기 위한 명시적 샘플 데모

## OpenAI 사용

Responses API + strict JSON schema. 작업 후보와 시간 제약에서 Mission을 생성하고, 막힘의 원인을 입력하면 다음 행동을 제안합니다. 실제 토큰 사용량과 호출 실패를 표시합니다. 일정 계산, 문구 검사와 해시는 결정적인 코드로 처리합니다.

## 2분 시연

**0:00–0:15**
“오늘 할 일은 많았는데, 끝낸 결과물이 없던 적 있나요? ShipOne은 오늘 하나를 정하고, 끝났는지 근거로 확인합니다.”

**0:15–0:40**
샘플 체험 → 오늘의 하나 골라줘.
“90분 작업을 억지로 추천하지 않습니다. 일정 사이의 연속된 시간과 우선순위를 반영해 하나를 고릅니다. 이 화면은 재현 가능한 샘플 계획이며 실제 Windows 버전은 OpenAI를 호출합니다.”
완료 조건을 보여주고 시작합니다.

**0:40–1:00**
생각 주차에 ‘나중에 모바일 기능 구상’ 입력.
“새 아이디어를 잃지 않으면서 지금의 Mission을 지킵니다.”

**1:00–1:30**
끝났는지 확인하기 → “신청 안내 누락” → 검사.
“서비스 이름과 분량은 맞지만, 약속한 신청 문구가 없습니다. 지금은 완료할 수 없습니다.”
“수정된 결과물” → 다시 검사.
“수정하면 이전 검사부터 무효화됩니다. 새 근거에서 세 조건을 다시 확인합니다.”

**1:30–1:50**
완료 기록 남기기 → 기록 저장.
“확인한 내용, 시각과 해시가 남습니다. 자동으로 확인하지 못하는 기능은 사용자 확인으로 분리합니다.”

**1:50–2:00**
“오늘의 하나를 고르고, 실제로 끝내는 동료. Windows 앱부터 개인 베타로 운영하고 모바일로 이어가겠습니다.”

## 실제 API를 연결한 경우의 시연 교체

샘플 대신 실제 작업으로 돌아가 개인 테스트 작업 2~3개와 일정을 입력합니다. 설정에서 키를 저장하고 추천을 호출합니다. 발표 때 키 입력 화면을 녹화하거나 노출하지 않습니다. 모델 응답 지연에 대비해 샘플 체험도 준비해둡니다.

## 현재 구현과 향후 범위

구현: Windows 설치 파일, 반응형 웹 데모, Mission/검증/기록, OpenAI 어댑터, Notion 읽기, Google 읽기 전용 OAuth, 파일/URL 검사.
향후: APK/IPA 스토어 출시, 기기간 동기화, 운영자 OAuth 앱, 선택적 자동 체크인.
실제 계정 연동 검증 상태는 VALIDATION.md를 따릅니다.

## 심사 질문에 대한 답변

**왜 LLM이 필요한가?** 시간 계산은 코드가 하지만, 다양한 작업을 실행 가능한 단계와 의미 있는 완료 조건으로 바꾸는 데 모델을 사용합니다. 막힘의 자유로운 설명도 다음 행동으로 변환합니다.

**AI가 완료를 잘못 판단하면?** 자동 판정은 명시적 검사에 한정합니다. 텍스트가 있다고 제품 전체가 정상이라고 선언하지 않습니다. 주관적 항목은 사용자 확인입니다.

**계속 사용할 이유는?** 하루에 실제 끝낸 결과물과 예상/경과시간이 쌓입니다. 향후 개인별 예상시간 보정과 연결 도구별 검증기를 개선할 수 있습니다. 현재 성장 가설이며 사용자 검증이 필요합니다.

**웹이 제품인가?** 제품 중심은 설치형 PC 앱입니다. 웹은 시연용이고, 모바일 앱 출시는 다음 단계입니다.
